# A3 모드 — 품질 이슈를 PDCA 한 장으로 끝까지 끌고 가기

도요타 A3 보고서(문제 → 현상 → 목표 → 원인 → 대책 → 실행 → 효과 확인 → 표준화를 한 장에)를 회사 양식에 맞춘 모드.
지금의 4단 구조(배제 원인 → 가설 → 확인 계획 → 리스크 조치)는 **원인 찾기**까지만 다룬다. A3는 그 뒤의
**"어디까지 줄일 건데?"(목표)** 와 **"그래서 끝났어?"(효과 확인)** 를 칸으로 강제한다. 상무가 종결을 묻는 질문에 답하는 칸이다.

## 언제 쓰나
| 상황 | 모드 |
|---|---|
| 시장 불량·고객 클레임·시험 NG 등 **종결까지 관리할 이슈** | A3 |
| 이슈 진행 중 정기 보고(주간·월간) — 같은 A3를 칸 상태만 바꿔 갱신 | A3 |
| 규격 검토·기술 설명처럼 대책·효과가 없는 주제 | 일반 생성 모드 (A3 쓰면 칸이 억지로 채워짐) |
| 원인만 찾는 단계, 대책은 아직 | 일반 모드의 4단 구조. 원인 확정 후 A3로 전환 |

"A3로", "PDCA로", "종결 보고", "이슈 관리 장표" 같은 요청이면 이 모드.

## 문서 구성
1. **1장 = A3 한 장** (`D.a3Slide`) — 상무는 이 장만 본다. 8칸 각 1~3줄.
2. **2장~ = 칸별 근거** (일반 부품) — 칸이 길어지면 상세는 뒷장으로 빼고 칸에는 "상세 Np"만. 보통 ② 현상 파악(추이 차트), ④ 근본 원인(원인 분류·사진), ⑦ 효과 확인(전후 비교)이 근거 장을 가진다.
3. 유첨 — 원본 수치·출처.
A3 한 장만 요청하면 1장만 만든다.

## 8칸과 작성 규칙
| 칸 | 답할 질문 | 반드시 들어갈 것 | 검사(check_a3.py) |
|---|---|---|---|
| ① 문제 정의 | 무엇이 문제인가 | 언제·어디서·몇 건·고객 영향 | 숫자 없으면 경고 |
| ② 현상 파악 | 지금 얼마나 나쁜가 | 현재 수준(숫자)과 기준 | — (근거 장에 차트) |
| ③ 목표 | 어디까지, 언제까지 | **목표 수치 + 기한** | 없으면 **실패** |
| ④ 근본 원인 | 왜 생겼나 | 원인 + 확신도([확인됨]/[추정]) | 확신도 없으면 경고 |
| ⑤ 대책 | 무엇을 바꾸나 | 임시 대책 / 영구 대책 구분 | 구분 없으면 경고 |
| ⑥ 실행 계획 | 누가 언제 | **담당 + 기한** | 없으면 **실패** |
| ⑦ 효과 확인 | 효과를 어떻게 아나 | **측정 지표(숫자)**, 아직이면 **측정 계획 + 날짜** | 둘 다 없으면 **실패** |
| ⑧ 표준화·횡전개 | 다시 안 생기게 | 설계 기준·체크리스트 반영, 타 모델 전개 | — |

- **모르는 칸은 비운다.** `text`를 비우면 빨간 점선 `[확인 필요] (필요한 것)`으로 그려진다. 그럴듯한 문장으로 채우는 것보다 빈칸을 보여주는 게 낫다 — 회의에서 "이 칸 누가 언제 채우나"로 바로 매듭지을 수 있다.
- 원본에 없는 목표치·담당·기한을 만들지 않는다. 원본에 없으면 빈칸.
- 칸 상태 `state`: `done`(완료) / `now`(진행) / `plan`(계획) / `risk`(리스크). 주간 갱신 때는 이것만 바꿔도 진척이 보인다.
- 칸 글은 개조식 1~3줄, 칸당 60자 안팎. 넘치면 상세를 근거 장으로.
- 핵심 메시지는 **이슈의 현재 위치**: "원인 확정, 대책 적용 중 — 효과 확인 12월" 처럼 PDCA 어디까지 왔는지.

## 코드
```js
const { slide, areas } = D.a3Slide(pres, {
  title: "오븐레인지 릴레이 융착 개선",
  message: "원인 확정, 상위 용량 릴레이 적용 중 — 효과 확인 12월",
  sub: "9월 회수품 12건 기준",
  planMsg: "접점 용량 부족이 주원인 [확인됨]",      // 선택
  actMsg: "대체 릴레이 11/30 적용, 12월 효과 측정",  // 선택
  plan: [
    { key: "problem", state: "done", text: "9월 시장 회수 12건, 가열 안 됨 클레임" },
    { key: "current", state: "done", text: "월 3~4건 발생 추이", w: 2, draw: true },  // draw → 아래 영역에 차트
    { key: "goal",    state: "now",  text: "12월까지 월 0건" },
    { key: "cause",   state: "done", text: "접점 용량 부족 7/12건 [확인됨, 표면 분석]" },
  ],
  act: [
    { key: "action",   state: "now",  text: "임시: 출하 전 접점 저항 전수 검사\n영구: 상위 용량 릴레이 대체" },
    { key: "plan",     state: "now",  text: "대체 릴레이 적용 11/30 (회로품질 ___)" },
    { key: "check",    state: "plan", text: "" },   // 비우면 [확인 필요] 측정 지표 + 측정 일정
    { key: "standard", state: "plan", text: "릴레이 선정 기준서에 돌입전류 마진 반영" },
  ],
  source: "※ 출처: ○○ 분석 보고서(10/28)", notes: "원본 #1~#12",
});
D.chartLine(pres, slide, areas.current, { labels: [...], series: [...] });  // draw:true 칸에만 areas가 생김
```
- `w`: 칸 높이 비중(기본 1). 차트·표를 넣을 칸은 1.8~2.2. 그림 영역이 0.6in보다 작으면 경고가 뜬다.
- `draw` 칸의 글은 1~2줄로. 표를 넣을 때 행 높이는 0.25in 이상(그보다 작으면 PowerPoint가 행을 늘려 아래 칸을 침범함) — 행이 4개 넘으면 근거 장으로 뺀다.
- 칸 순서·이름은 고정(`problem current goal cause | action plan check standard`). 칸을 빼지 않는다 — 해당 없으면 "해당 없음 (이유)"를 쓴다.

## 스토리보드 형식 (A3 장)
```
## 1장 [A3]
- 소제목: ...
- 핵심 메시지: (PDCA 어디까지 왔나)
- ① 문제 정의: 상태=done / 글=... / 출처=...
- ② 현상 파악: 상태=done / 글=... / 그림=chartLine(데이터=...) / w=1.4
- ③ 목표: 상태=now / 글=(없으면 빈칸)
- ④ 근본 원인: ...
- ⑤ 대책: ...
- ⑥ 실행 계획: ...
- ⑦ 효과 확인: ...
- ⑧ 표준화·횡전개: ...
- 빈칸 목록: (사용자에게 물을 것 — 담당·기한·목표치)
```
체크포인트 질문에 **빈칸 목록**을 반드시 넣는다. 사용자가 답하면 채우고, "진행"이면 빈칸 그대로 만든다.

## 검수 질문 (A3 장 추가)
- 상무가 "그래서 끝났어? 언제 끝나?"라고 물으면 ③·⑦ 칸에서 바로 답이 보이는가
- 칸 상태(완료/진행/계획)만 훑어도 PDCA 어디까지 왔는지 보이는가
- 빈칸이 숨겨지지 않고 빨간 점선으로 보이는가
