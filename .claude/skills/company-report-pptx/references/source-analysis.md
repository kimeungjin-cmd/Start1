# 1단계: 원본 분석·구조화

PPT를 그리기 전에 반드시 이 단계를 끝내고 사용자 확인을 받는다. 결과물 품질은 여기서 결정된다.

## 대원칙
- **수치와 사진은 버리지 않는다. 위치만 정한다.** (본문 / 본문 주석 / 유첨)
- **연결은 추측하지 않는다.** 근거가 약하면 `[연결 확인 필요]`로 표시한다.
- **이 단계에선 요약하지 않는다.** 원문 그대로 옮기고 위치를 적는다. "조건부 합격", "일부 시료에서" 같은 조건·범위 표현이 요약 중에 사라지는 것이 가장 흔한 사고다. 요약은 스토리보드에서만.

## 대용량 기술문서 모드 (데이터시트·규격서·매뉴얼, 대략 50쪽 이상)
"전부 변환"이 의미 없는 원본이다. 원칙을 바꾼다.
- **먼저 목적을 묻는다** (부품 사양 요약 / 회로 설계 검토 / 특정 기능 적용 검토 / 목차형 요약). 목적이 뽑을 범위를 정한다.
- **수치 보존 → 출처 보존**: 목적에 필요한 수치만 본문에, 모든 수치에 원본 쪽 번호를 붙인다(칩 형태 "p.305"). 마지막에 **원본 쪽 추적표**(주제 / 원본 위치 / 본문 장 / 추가로 볼 곳) 유첨.
- 누락 검사(check_coverage)는 원본 전체 대상으로 돌리지 않는다. 대신 본문 수치를 원본 쪽에서 다시 대조한다.
- 문서 정체를 먼저 확인한다: 제품 종류(사용자가 말한 것과 다를 수 있음), 등급(Automotive 등), **개정번호·날짜·Preliminary 여부**. 보고서 부연설명에 기준 문서를 적고 최신판 대조를 리스크로 남긴다.
- 그림·회로는 원본 쪽을 렌더링해서 잘라 쓴다(다시 그리지 않음). 그림 번호와 쪽을 캡션에.
- 산출물 끝에 **체크리스트**(항목 + 쪽 번호 + 판정 칸)를 두면 검토 회의에서 바로 쓴다.

## ① 원본 목록표 (텍스트·수치)
| 번호 | 원본 위치 | 원문 | 유형 | 성격 |
|---|---|---|---|---|
| #1 | p.2 2문단 | 9월 회수품 12건 중 7건 접점 용착 | 근거 | 사실 |

- 유형: 결론 / 근거 / 배경 / 조치 / 조건·기준
- 성격: 사실(데이터·관찰) / 의견(작성자 판단) / 추정(가능성 표현)
- 수치는 단위·소수점·측정 조건까지 원본 그대로 적는다.
- 30쪽 이상 긴 문서: 수치·그림·결론 문장만 개별 목록화하고 나머지는 쪽 단위로 묶는다.

## ② 사진 목록 (별도 관리)
| 번호 | 원본 위치 | 사진 내용 | 연결된 설명 | 연결 근거 | 배치 |
|---|---|---|---|---|---|
| P1 | p.3 상단 | 접점 표면 용착 흔적 | #8 | 캡션 "그림 2" | 본문 2장 |
| P3 | p.7 | 시료 외관 | 연결 확인 필요 | 근처 설명 없음 | 유첨 |

연결 근거는 강한 순서대로 본다.
1. 번호 참조 ("그림 3", "사진 ①")
2. 본문 지시어 ("아래 사진과 같이", "우측 X-ray 참조")
3. 위치 (같은 쪽·슬라이드, 바로 옆·아래)
4. 사진 속 표시 (화살표, 원, 라벨)
5. 사진 내용을 보고 한 판단 — 가장 약함. 이것만 남으면 `[연결 확인 필요]`

PDF 속 이미지는 세로 띠·가로 조각으로 쪼개져 있는 경우가 많다(실제 테스트에서 표 캡처·속기록 모두 조각남). 이미지 개수가 이상하거나 크기가 가늘면(예: 5×540px, 595×135px 여러 장) 조각 추출을 포기하고 **쪽 전체를 이미지로 렌더링**(예: `pdftoppm -png -r 110`)한 뒤 필요한 영역을 잘라 쓴다. 쪽 전체 이미지는 유첨에, 잘라낸 부분은 본문에. 잘라낸 영역이 쪽 경계를 넘으면 검은 띠가 생기니 쪽 크기 안에서 자른다.
**엑셀 원본(회의록·체크시트 등)**: 사진은 셀 위에 떠 있다. openpyxl `ws._images`의 앵커(`anchor._from.row`, `anchor.to.row`)로 **시작 행 = 해당 행의 항목 번호**에 연결한다. 사진이 여러 행에 걸쳐 있거나, 한 행에 사진이 여러 장이고 옆 행에 사진이 없으면 `[연결 확인 필요]` 후보로 보고 내용을 눈으로 대조한다.
엑셀·PPT 원본은 사진에 **회전·자르기 속성**이 걸려 있을 수 있다(`xl/drawings/drawing1.xml`의 `<a:xfrm rot="5400000">` = 시계방향 90°, `10800000` = 180°, `<a:srcRect>` = 자르기). 원본 파일을 그대로 꺼내면 누운 사진이 되므로 **원본 화면에 보이는 방향대로 보정**해서 쓴다.
사진이 많으면(20장 이상) 번호를 붙인 썸네일 모음을 만들어 한 번에 대조한다.
추출 직후 사진 썸네일을 사용자에게 한 번 보여준다. 조각난 PDF 이미지, 이미 잘린(크롭) 원본, 저해상도 미리보기를 이때 잡는다.
회로도·도면은 AI가 다시 그리지 않는다. 원본을 그대로 쓰고 필요한 부분만 자른다.
이미지로 된 그래프에서 숫자를 읽어 다시 그리지 않는다(값이 틀어진다). 원본 PPT의 기본 차트는 데이터째 가져와 다시 그려도 된다.

## ③ 빈칸·불일치 점검 → 확인 필요 질문
보고에 필요한데 원본에 없는 것, 그리고 **본문 주장과 첨부 데이터가 다른 곳**을 찾는다. (예: 본문은 "대표에게 상여금 지급", 첨부 표에는 직원 상여금도 같은 금액 → 그대로 옮기지 말고 질문으로 올린다. 검토 모드에서는 이게 첫 번째 지적사항이 된다.)
- 결론이 없다 / 판정 기준이 없다 / 담당·기한이 없다 / 시료 수·조건이 없다 / 원인 미확정인데 확인 계획이 없다
질문은 짧게 목록으로. 답을 지어내지 않는다.

## 수치 보존의 예외: 개인정보
휴대폰 번호, 개인 주소·우편번호, 주민등록번호, 계좌번호 등 개인정보는 보고서에 넣지 않는다. 대신 무엇을 뺐는지 사용자에게 알리고, 누락 검사 때 `--ignore`로 명시한다. 회사·기관 주소의 번지수처럼 보고와 무관한 숫자도 같은 방식으로 처리한다.

## 원본이 PPT일 때
- 같은 구조가 반복되는 장(챕터·항목별 1장씩)은 **3단 레이아웃으로 3개씩 묶어** 장 수를 줄일 수 있다. 각 칸의 정보 항목은 하나도 빼지 않는다.
- 원본의 개요 장과 본문 장이 서로 맞는지 대조한다(예: 개요 흐름도에 없는 장이 본문에 있음). 불일치는 질문으로 올리고, PPT에선 점선 등으로 '원본에 없던 보완'임을 표시한다.
- 원본의 이모지·장식은 옮기지 않는다. 의미가 있으면 칩·번호·색으로 바꾼다.

| 장 | 핵심 메시지 | 레이아웃 | 박스 메시지(좌/우) | 박스 유형 | 원본 항목 |
|---|---|---|---|---|---|
| 1 | 접점 용량 부족이 유력 원인 | 2-55 | 12건 중 7건 / 제조 불량 배제 | 차트형 / 4단 구조형 | #2 #5 #8~11 P1 |

- 원인 미확정 이슈: 배제 원인 → 유력 가설 → 확인 계획·날짜 → 리스크 조치.

## ⑤ 사용자 확인
스토리보드 + 확인 필요 질문 + 사진 썸네일을 보여주고 OK를 받은 뒤 PPT를 만든다.
검토 모드에서는 ①~③과 원본 요약까지만 하고 PPT는 만들지 않는다(SKILL.md 참조).
