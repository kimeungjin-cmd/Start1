# 문체·AI 티 제거

## 기본 문체
- 개조식, 명사형 종결 (~함, ~임, ~필요, ~예정)
- 핵심 메시지 1줄(45자 이내), 결론부터. 숫자가 있으면 숫자로
- 형용사 대신 숫자: "크게 개선" ✗ → "불량률 0.8% → 0.3%" ○
- 결론은 담당·기한까지: "추가 검토 필요" ✗ → "11/20까지 재현시험 (회로품질)" ○
- 숫자 단위·소수점 자리 통일, 원본 정밀도 유지

## 금지어 (scripts/check_text.py와 동기화)
다양한, 효과적으로, ~를 통해, 다음과 같습니다, 혁신적, 중요한 역할, 시사점을 제공, ~에 있어서, ~하는 것이 필요합니다, ~할 수 있습니다, ~것으로 보입니다
주의: "제고", "고도화", "방안 마련"은 사내 보고서에서 정상적으로 쓰는 말이라 금지어가 아니다. 금지어는 부서 보고서 기준으로 추가한다.

## AI 티 패턴
- 항목을 무조건 3개씩 맞추기
- 핵심 메시지가 소제목을 다시 말하는 수준
- 굵은 글씨·기호·영어 병기 남발, 이모지
- 같은 말이 핵심 메시지·박스 메시지·본문에 반복
- 출처 없는 그럴듯한 일반론 ("오전이 가장 붐빈다" 같은 문장) → 근거 없으면 삭제

## 신뢰도 표시
- 원본·검색 근거가 있는 사실만 단정형으로
- 추정은 "추정"이라고 쓰거나 부연설명에 조건을 적는다
- 웹 검색 자료는 장 하단 출처 주석 필수

## 두 층 독자: 상무가 이해하고, 실무자가 검증할 수 있게
최종 독자는 상무, 전달자는 파트장이다. 상무는 이해가 빠르다. **쉽게 풀어 주는 것보다 '꼼꼼히 검토했고 판단이 논리적인가'를 본다.** 그래서 기초 용어 풀이는 하지 않고(가전 고유 용어만 짧게), 대신 **검토의 흔적**을 반드시 보여준다.

**검토의 흔적 4요소** (1장 또는 핵심 판단 장에 넣는다)
1. 검토 범위: 무엇을 얼마나 봤나 (자료·시료 수·기간·건수)
2. 판단 기준: 무엇에 비춰 판단했나 (스펙·규격 조항·과거 사례)
3. 배제한 것과 이유: 다른 가능성을 왜 아니라고 봤나
4. 확신도와 남은 확인: [확인됨]/[추정], 무엇을 언제까지 더 확인하나

**장 배치**
- 1장 = 상무용 한 장: 결론 / 고객·시장 영향 / 결정·요청 사항. 전문용어 없이 읽혀야 한다.
- 본문 = 논리: 원인 미확정이면 배제 원인 → 유력 가설 → 확인 계획·날짜 → 리스크 조치.
- 유첨 = 기술 상세: 측정값, 규격 조항, 회로·데이터. 본문에서 "상세: 유첨 N"으로 연결.

**쉽게 만드는 5가지 (논리는 그대로)**
1. 가전 고유 용어만 처음 나올 때 짧게 풀이(기초 HW 용어는 풀지 않음): "BOD(전원 강하 시 자동 리셋)"
2. 숫자는 기준과 함께: "9도" ✗ → "9도 (스펙 0~8도, 1도 초과)" ○
3. 인과는 한 줄 사슬로: 원인 → 현상 → 고객 영향 → 조치
4. 영향은 상무의 언어로: 시장불량 건수, 비용, 일정, 고객·법규 리스크
5. 메커니즘은 글보다 그림: 블록도, 사진 + 화살표, 전후 비교

**같은 내용, 두 층 예시**
- 실무용(유첨): BODLEVEL=100 설정, VBOT 4.0/4.3/4.6V (min/typ/max)
- 상무용(본문): 전원이 4.3V 아래로 떨어지면 자동 리셋 → 저전압 오동작·데이터 손상 방지

**검수 질문 추가**
- 파트장이 질문 없이 그대로 상무에게 올릴 수 있는가?
- 검토 범위·판단 기준·배제한 것·확신도가 보이는가? ("어디까지 봤어?"에 장 안에서 답이 되는가)
- 풀이 없이 쓴 전문용어가 1장에 남아 있지 않은가?
- 모든 숫자 옆에 기준이나 비교 대상이 있는가?

## 줄바꿈 — 줄이 바뀌어도 잘 쓴 한국어 문장으로
- 두 줄 이상이 되면 **의미 단위에서 직접 끊는다**(쉼표 뒤, '→' 앞, 주어부·서술부 사이). 자동 줄바꿈에 맡기지 않는다.
- 마지막 줄에 한 어절만 남으면(외톨이 줄) 문장을 줄이거나 끊는 위치를 바꾼다. 상자를 넓히는 건 마지막 수단.
- 줄을 조사(은·는·을·를·의·에…), 닫는 괄호, 쉼표로 시작하지 않는다.
- 숫자와 단위(16시, 30분, 219만원, 4.5V)는 같은 줄에. 괄호 안 내용도 한 줄에.
- 각 줄이 따로 읽혀도 뜻이 통하게: "계획대로 판다 →\n사파리" ✗ / "계획대로\n판다 → 사파리" ○
- HTML 그림(Playwright)은 CSS에 `word-break: keep-all`을 넣어 단어 중간에서 끊기지 않게 하고, 두 줄이 될 문장은 `<br>`로 직접 끊는다.

## 제목 번호와 페이지 번호
- **소제목에 '1. 2. 3.' 번호를 붙이지 않는다(기본).** 소제목은 메시지를 전하는 자리이고, 번호는 장 순서를 바꿀 때마다 고쳐야 한다. 유첨만 '유첨1.'처럼 표시한다.
- 예외: 목차가 있는 10장 이상 문서는 큰 묶음 번호(Ⅰ, Ⅱ, Ⅲ)만 소제목 앞에 붙인다.
- **페이지 번호는 항상** 오른쪽 아래에 작게 "현재 / 전체" 형식(deck.js의 `D.save`가 자동 삽입. 현재 번호는 장 순서를 바꿔도 자동 갱신, 전체 수는 저장 시점 기준이라 손으로 장을 추가하면 다시 생성하거나 직접 고칠 것). 본문·자가점검에서 다른 장을 가리킬 때는 이 번호를 쓴다("상세: 5장").
- 회사 양식 원본에 페이지 번호 위치·형식이 따로 있으면 그것을 따른다.
- `reserveCover: true`로 저장하면 표지를 붙이기 전엔 본문 첫 장이 '1 / 전체'로 보이고, 표지를 맨 앞에 붙이면 '2 / 전체'로 맞춰진다(정상).
